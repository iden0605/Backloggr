# Plan

_Last updated: 2026-07-02_

## Current Phase

Stage 5 (Cloudflare Worker + AI recommendations) functionally complete, but a round of live testing surfaced UI/UX bugs and AI-quality issues — those are scoped as Stage 5.5 before moving on to Stage 6 (ffmpeg clip capture + hotkey).

## Goals

- Build out backlog management (RAWG search, add/edit/status) end-to-end, with as little manual data entry as possible (auto-add on launch now; full Steam library import later)
- Layer in auto playtime tracking, dashboard analytics, AI recommendations, and clipping
- Ship a working Windows installer via CI/CD

Verified via `cargo check` and `tsc --noEmit`; user testing live with Dave the Diver in progress.
- Auto-add-to-backlog (user feedback: didn't want to manually add every owned game): tracker now detects games launched from Steam/Epic/GOG/Battle.net/Riot install paths that aren't already in the backlog, best-effort enriches via RAWG, and adds + starts tracking them with zero manual steps. Full Steam-account library import (sign-in based, covers never-launched games too) intentionally deferred to Stage 10 — see Steps table task 17.
- Auto-add name matching + delete bug fixes (found via live testing with Bloons TD 6): RAWG search now humanizes storefront folder names before matching (fixed missing cover art); `delete_game` now cleans up dependent `sessions`/`clips` rows in a transaction (fixed a foreign key constraint error that blocked deleting any previously-tracked game). Both confirmed fixed by the user live.
- Backlog v2 (user feedback: the status dropdown wasn't useful/discoverable): status now auto-updates to `playing` when the tracker detects a launch; Backlog UI reorganized into status-grouped sections with contextual action buttons and inline playtime instead of one flat list + dropdown per row. Verified via `cargo check` and `tsc --noEmit`; live user testing pending.
- Full Stage 5 + chat recommendations (expanded scope, user request): deployed `proxy/src/index.ts`, a Cloudflare Worker proxying to **Groq** (not Ollama — free tier, no self-hosting) with a system prompt constrained to strict `{"type":"clarify"|"search", ...}` JSON. New Rust `chat_recommend` command forwards chat turns, and runs `rawg::search_games` itself once the model signals it's ready — RAWG key never touches the worker. `Recommendations.tsx` is now a chat UI (in-memory history only, per user's explicit choice) that can ask one clarifying question before showing results. Also added `rawg::get_game_details` (RAWG's `/games/{id}` for description/Metacritic/developer/publisher/website) and a shared `GameCard` component (compact grid card + click-to-expand detail panel) used by both `Recommendations` and `Search`, replacing Search's old bare card markup. User deployed the worker themselves via `wrangler deploy` + a registered `*.workers.dev` subdomain; verified via `cargo check`, `tsc --noEmit`, `npm run build`, and a clean `npm run tauri dev` launch (no panics).
- Stage 5 iteration round (live user testing found real quality/UX issues, fixed same session):
  - Chat quality: RAWG's plain keyword search surfaced a wall of same-title reskins (e.g. "Farming Simulator 2013/15/17/19/22" for "games like Stardew Valley") — fixed by having Groq name specific distinct titles it knows (`titles: string[]`) and resolving each individually via new `rawg::resolve_titles`, capped at 8 results.
  - Worker URL hardcoded as a Rust const instead of a user-facing Settings field (user explicitly wanted it hidden, same pattern as the RAWG key) — added then removed `get_setting`/`set_setting` commands and the Settings UI field in the same session.
  - Added a Dashboard-activity-based recommendation source: `get_dashboard_recommendations` picks the user's top-played genre + 3 favorite games, calls the worker's new `/suggest` endpoint, and caches the result in a new `dashboard_recommendations_cache` table (single row) — only regenerates on a 5-hour timer, backlog-size change, top-genre change, or a 2-hour jump in that genre's playtime, so it isn't an AI call on every page load. Later moved from a Dashboard widget into a "For You" tab on the Recommendations page (user request) — Dashboard no longer shows AI recommendations.
  - Fixed the chat always searching immediately even on a first, vague message ("give me a new game") — the model wasn't reliably self-judging "should I clarify or search" from prose alone. Rewired to a deterministic contract: the frontend explicitly sends `awaitingAnswer` (true = this message answers a pending clarifying question, false = new ask), and the worker picks between two separate system prompts based on that flag rather than asking the model to decide. Conversation history is no longer truncated between asks (an earlier fix had reset it after every results turn to avoid unrelated-topic bleed, but the user wanted continued/deepening conversations instead — the explicit flag makes the reset unnecessary).
  - Fixed the clarifying question always asking the same generic "what aspect appeals to you" regardless of prompt specificity (e.g. still asked that for "MMORPG with classes and races", which already answered several axes) — rewrote `CLARIFY_SYSTEM_PROMPT` to have the model reason about what the request does NOT yet specify (setting/theme, tone, pacing, difficulty, social angle, art style, specific mechanic) and pick a non-repeating axis, instead of defaulting to one canned question shape.
  - Added multi-select clarifying questions (`multiSelect` field end-to-end: worker → `chat_recommend` → frontend) with a checkbox-style option UI + "Continue" button, for questions like "what do you like about X" where more than one answer applies; single-choice questions still send immediately on click.
  - UI fixes: results now show an explicit "Here are some games based on..." lead-in line above the grid (both Chat and For You tabs); `GameCard`'s expanded panel puts genre/Metacritic on one row and platforms on a separate row (was cramped on one line); `GameCard`'s compact layout is a flex column with the "Add to Backlog" button pinned to the bottom via `mt-auto` (was misaligned across a grid row depending on genre/platform line count); platform icons collapse to at most 4 deduped category icons (Windows/Mac/Console/Mobile) instead of one icon per individual RAWG platform entry (was showing e.g. 4+ repeated controller icons for PS4/PS5/Xbox One/Xbox Series).
  - Remaining known bugs/quality issues (RAWG link click not opening, chat bubble sizing, no smooth-scroll, input disabling while AI loading, generic placeholder copy) deliberately deferred to Stage 5.5 — see Steps table task 12b.

## Decisions

- Marketing website will live in a **separate repo**, not this monorepo. This repo is app-only (+ future `proxy/` for the Cloudflare Worker). The site will pull the latest release info from the GitHub API rather than sharing code with this repo.
- Development happens on macOS; the real target is Windows. Windows-only pieces (`gdigrab` capture, registry-based launch-on-startup, `.msi` build) can't be tested locally on Mac — they'll be validated via the GitHub Actions Windows runner and, eventually, manual testing on real Windows hardware.
