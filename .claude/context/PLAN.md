- Stage 6 — ffmpeg rolling-buffer clip capture + hotkey (task 13), through several live-testing iteration rounds to its final architecture: `clipper.rs` runs ONE continuous ffmpeg capture per game session (`ensure_capture`, called from `tracker.rs` at session open/close — never stopped/restarted on focus changes) writing MPEG-TS segments (`-segment_wrap`, 10s segments, 3-min ring buffer in `<appdata>/clip_buffer/`) plus an AAC mic track. `Alt+F9` (hardcoded global shortcut, same pattern as the RAWG key/worker URL) calls `save_clip`, which re-encodes (not stream-copy — needed for exact-length output seeking and the black-out filter below) the trailing N seconds into `<appdata>/clips/`, attached to whichever game has an open session.
  - **Continuous-buffer design, not pause/swap**: two earlier architectures (dropping tainted segments at save time; live-killing and swapping ffmpeg for a black-frame generator on every focus change) both proved buggy under real tab-out testing — swap-kills produced 0-byte segments, broke duration math (clips came out 24-40s instead of the requested 30), and mask timing drifted enough to invert which span got blacked out. The fix, confirmed by the user to match how Medal/ShadowPlay/Outplayed work: never stop the buffer: a 1-second focus sampler (`is_frontmost`, `lsappinfo` on macOS — NOT `osascript`/System Events, which silently fails without an Automation permission dev binaries never get prompted for) just logs focus state; `save_clip` masks the logged unfocused ranges to solid black in the OUTPUT via an ffmpeg `drawbox...enable=` filter, anchored on the selected segments' own precise file timestamps (an earlier version anchored on `now() minus a summed-duration estimate`, which drifted and blacked the wrong span). Only applies when capture isn't window-scoped — Windows' `gdigrab title=` capture structurally can't contain non-game content regardless of focus, so real gameplay records straight through alt-tabs there with no masking needed at all (this is genuinely superior to the Mac dev-only fallback, matching the "GPU/window hook" tier of capture the user's research called out for tools like Medal).
  - **Self-healing against orphaned capture processes**: dev rebuilds (and, on shipped installs, crashes/force-kills) can kill the app without running its exit cleanup, orphaning the capture ffmpeg — which then keeps recording indefinitely into a buffer a fresh app instance would read from. Each spawn writes its PID to `capture.pid`; `reap_orphan_capture` (called at app startup and before every fresh capture spawn) kills a leftover process found there after verifying it's still actually an ffmpeg (PIDs get reused). `tauri-plugin-single-instance` also prevents two copies of the app running at once, which was independently capable of causing the same symptom.
  - **Mic audio**: added end-to-end (macOS `avfoundation` combined video:audio input; Windows auto-detects the default `dshow` device) and captured continuously through tab-outs — only the video gets masked, never the audio track. Falls back to video-only after 2 consecutive capture-spawn failures (`CaptureSlot::respawn_strikes`) rather than crash-looping if the audio input is the problem. Not yet exposed as a user toggle — see task 13b.
  - Exact clip length: `recent_segments` returns the real wall-clock span the selected segments cover (from file birth/modified times, not an assumed 10s-per-file), and `save_clip` uses `-ss`/`-t` on the re-encode to cut precisely the requested trailing window.
  - Native notifications: the `tauri-plugin-notification` path silently does nothing for unbundled `cargo run` dev binaries on macOS (permission reads Granted, `.show()` returns Ok, nothing appears) — worked around by shelling to `osascript -e 'display notification...'` on macOS specifically, Windows/packaged apps use the plugin normally. **Still not confirmed working live on macOS as of the last test** — see task 13b, this needs further debugging, the `osascript` workaround may not be sufficient on its own.
  - Ffmpeg is still a bare PATH lookup — bundling it as a Tauri sidecar binary remains deferred to the release-workflow stage (16).
  - `Clips.tsx` shows a thumbnail grid with a click-to-play modal (`convertFileSrc`, asset protocol scoped to `$APPDATA/clips/*`). Settings has a working clip-length field (`get_clip_seconds`/`set_clip_seconds`, backed by the `settings` table).

- Task 13b round 1 (gradient mask, saving-state toast, mic toggle) + round 2 (live-test bug fixes and the in-game overlay). The user's first live test found five real bugs, all root-caused and fixed the same session:
  - **Empty/unplayable 262-byte clips**: `-segment_wrap` recycles segment files in place and recycled files keep their ORIGINAL creation time (macOS), so once the ring wrapped (~3 min in) the birth→mtime duration math inflated wildly, pushing the output `-ss` seek past the real footage — ffmpeg exits 0 having written a zero-frame MP4. `recent_segments` now derives each segment's span from mtime deltas between consecutive files (never birth times), stops selection at footage holes (delta ≫ segment length, i.e. capture died/respawned), and `save_clip` hard-fails (deleting the junk file) if the finished clip probes as zero-duration instead of cataloging it.
  - **No audio in clips**: the hardcoded avfoundation device string `"2:1"` had gone stale — audio index 1 on the dev machine is now BlackHole (silent virtual device), not the mic, because connected devices (JBL headset, iPhone) reorder the list. Devices are now resolved at every spawn: screen index parsed by name from `-list_devices` output, audio uses avfoundation's `default` keyword (follows the system-default input). Note game/system audio was never in scope on mac (needs loopback routing); mic-only is the current design, Windows WASAPI loopback is a future packaging-stage upgrade.
  - **10s saves**: the `geq` per-pixel gradient was the cost (per-frame expression eval at 2560×1664). The mask is now a pre-rendered PNG (`src-tauri/resources/tabbed_out.png`, vignette + "Tabbed out / Back in a moment" text baked in — generated with PIL, committed as an asset, bundled via tauri.conf `bundle.resources`) composited with `scale2ref`+`overlay=enable='...'`. 30s Retina save ≈ 4.6s total (verified with a real ffmpeg run); also kills the drawtext dependency entirely (`drawtext_supported()` probe removed). Falls back to flat-black `drawbox` if the resource is missing.
  - **Clips include the whole screen in windowed mode**: macOS clips are now cropped to the game window at save time — `game_window_rect_points()` (CGWindowListCopyWindowInfo via new macOS-only `core-graphics`/`core-foundation` deps; bounds need no TCC permission) finds the largest window of the game's pids, `crop_filter_for_game_window()` maps points→capture pixels using the probed segment resolution vs. display point size (avfoundation captures native panel pixels — neither point size nor backing size, so the scale MUST come from the actual footage). Fullscreen/whole-display windows skip the crop; off-main-display windows fall back to uncropped. Window position is sampled at save time, so a window dragged mid-clip shows offset early footage — accepted tradeoff. (Windows needs none of this: `gdigrab title=` is true window capture at the source.)
  - **Mic toggle didn't apply live**: the setting was only read at capture spawn. `set_mic_enabled` now kills the live capture with a `restart_requested` flag on `CaptureSlot`; the tracker watchdog respawns it (≤5s) reading the new setting, treating it as a fresh start (buffer wipe — segments with a different stream layout can't concat) and NOT counting an audio-failure strike. Also fixed the toggle knob CSS (missing `left` anchor made it overflow the switch).
  - **In-game overlay toast replaces OS notifications entirely** (user request — the Medal/ShadowPlay approach; macOS suppresses notification banners whenever a fullscreen app is frontmost, which the log proved was why "granted + osascript success" still showed nothing in-game): new `overlay.rs` creates a small (360×72) transparent, always-on-top, click-through, non-focusable window at app setup (main-thread requirement), hidden until `overlay::toast()` shows it pinned top-right of the primary display. Capability file now lists `clip-overlay` alongside `main` (a webview without a capability can't even `listen`). Known limit shared with all non-injecting overlays: Windows exclusive-fullscreen games won't show it (borderless is fine).
